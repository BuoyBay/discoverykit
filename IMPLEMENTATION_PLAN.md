# DiscoveryKit implementation plan

Implement an independent bounded DNS wire parser and query builder, plus an explicit-lifecycle IPv4 UDP session using Buoy's public UDPSocket APIs. No native bridge or dependencies are needed.

API: EncodeDNSName, BuildDNSQuery, ParseDNSMessage; DNSQuestion, DNSRecord, DNSMessage as detached mutable results; DiscoverySession.Open/SendQuery/HasPendingDatagram/Receive/Close and DiscoveryDatagram with peer metadata. Decode PTR/CNAME/NS targets, SRV metadata, binary TXT segments, A and AAAA, while preserving unknown raw record bytes. Names use trailing-dot presentation with decimal byte escaping to preserve opaque labels, dots and NULs without violating Buoy String constraints.

Limits: 63-byte labels, 255-byte expanded names, at most 128 compression-pointer jumps (labels/terminator do not count), bounded datagram bytes and total questions/records. Only backward compression pointers into DNS body are accepted. RDATA name consumption is bounded to its encoded field even when following compression pointers outside it. Reject truncation, reserved label encodings, oversized data/counts, malformed known RR payloads, and trailing bytes. TXT stays binary; zero-length TXT RDATA tolerates one empty string per RFC6763. No premature text decoding. DNSNameLabels exposes owned raw label bytes for explicit display decoding; SendQuery exposes the QU flag.

Transport: no socket or network activity until Open. Binding port 5353 and joining 224.0.0.251 requires explicit joinMulticast=True. Select receiving interface via public join API, set outgoing multicast TTL to 255. Default ephemeral Open supports legacy unicast mDNS replies. Query defaults to PTR and multicast destination, but tests use explicit IPv4 loopback destinations only. Close is idempotent. Receiver drains one datagram and rejects malformed input, leaving remaining queued datagrams for subsequent calls.

Out of scope: responder/advertising, conflict probing, cache/TTL expiration and merging, automatic retries/refresh, service assembly, incoming IP TTL validation (not exposed), IPv6 transport, outbound multicast interface selection (not exposed), wide-area DNS management, automatic SRV/TXT/address followup, DNSSEC or trust guarantees. Therefore describe as DNS-SD query/record building blocks and opt-in browser transport, not a complete Bonjour daemon replacement.

Validation: compiler JSON checks on source, tests and example for six desktop targets; real sealed-consumer execution on Linux. Deterministic independently generated Python wire fixtures verify query bytes, all supported RR kinds, compressed and escaped labels, uint32 TTL, cache-flush/QU flags, sections, unknown records, malformed pointer cycles/forward pointers, length limits, truncation and budgets. Local-only UDP session test exercises send, receive peer metadata, malformed datagram consumption, empty receive, close lifecycle. No multicast traffic during automated tests. macOS/Windows execution and a live multicast environment remain explicit unperformed manual checks.
